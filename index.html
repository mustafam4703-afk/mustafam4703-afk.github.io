About

I'm a First Class MEng Mechatronic Engineering graduate from the University of Manchester, now doing the MSc Robotics year of the RAINZ doctoral training centre before a PhD at the University of Glasgow.

Before that I spent twelve months at Renishaw as an embedded software engineer, writing C++ firmware for precision measuring machines. It taught me to build software that talks to real hardware, passes design review and holds up on the test bench.

Career objectives and research interests

I'm starting a PhD at the University of Glasgow through the RAINZ CDT (Robotics and AI for Net Zero). The project is on resilient teleoperation of ground robots: keeping a human operator in control when the communication link is delayed, lossy or under attack. The case study is inspection and maintenance of net zero energy assets.

My research interests:

  • Control and teleoperation over imperfect communication links
  • Human-machine interaction for remote operators
  • Low-power AI for real-time decisions on robots

Beyond the PhD, I want to work as a robotics systems engineer, somewhere firmware, control and operator interfaces meet.

Projects

Firmware-controlled tensile testing rig

Final-year team project, 2025 to 2026. C++, Python, ESP32-S3.

Control and measurement firmware for a mechanical rig that stretches material samples while recording force and displacement.

  • Stepper control on dedicated hardware peripherals, so step timing stays jitter-free whatever the processor is doing.
  • Load cell with a 24-bit amplifier, plus a glass linear scale decoded in hardware for ±10 µm displacement accuracy.
  • Python GUI with live telemetry, six real-time graphs and CSV export.
  • Found and documented a race condition between a motion pulse and a stop command, with a handover write-up of the fix.

Control code on GitHub

Robotic manipulator control

Module coursework, MEng Year 4, 2026. Python and NumPy.

Simulated controllers for robot arms, built as continuous-assessment notebooks that move from joint-space control to contact tasks.

  • PD control with gravity compensation, then joint-space inverse dynamics tracking a sinusoidal trajectory, on a 2-DoF planar arm.
  • Task-space inverse dynamics control for a circular end-effector path, with gains tuned to meet a tracking-error limit.
  • Hybrid force/motion control for a 7-DoF arm sliding along a surface: selection matrices, plus force feedback with feedforward.
  • Module result: 85.

CMM joystick emulator, Renishaw

Industrial placement, 2023 to 2024. Embedded C++.

Firmware that emulates a joystick control unit for a coordinate measuring machine, so the controller's behaviour could be observed and tested.

  • Implemented over RS-485 against a documented communication specification.
  • More than 100 unit tests written test-first with a C++ mocking framework.
  • Four UML state machines and over twenty class diagrams used in design reviews.
  • Bench-validated against real CMM controller hardware before formal code review.

Employer code is not public.

UART packet protocol

Personal project. C++, ESP32, GoogleTest and GMock.

A lightweight packet protocol for ESP32 serial links, with a custom binary framing format and XOR checksum validation. Built test-first, with mocks standing in for the hardware.

Source on GitHub

PID line-following robot

Second-year team project. Embedded C++, STM32F401RE.

A differential-drive robot that follows a line. I wrote the control code.

  • PID algorithm that steers the robot along the line, with gains tuned by experiment to improve tracking and reduce oscillation.
  • Hardware timers, interrupts and PWM driving the H-bridge motor drivers.
  • Optical encoder feedback for closed-loop control.

ROS 2 obstacle avoidance

Self-directed study. Python, ROS 2, Gazebo.

An autonomous obstacle-avoidance robot, proven in Gazebo and then deployed to a physical FastBot.

  • Laser scan split into five regions to choose a turn direction.
  • Sixteen-point heading tracking from odometry yaw.
  • Recalibrated the laser index mapping for the real robot (450 readings, against 660 in simulation) and re-tuned angular velocity after the defaults turned too slowly.

Leo Rover software, MSc team project

Work in progress, 2026. ROS 2 Jazzy, Python.

Robot software for a Leo Rover, built as part of the Robotic Systems Design Project in a team of MSc Robotics students.

  • A GUI controller package for driving the rover.
  • Odometry-based square-driving nodes, with separate versions for simulation and the real robot.
